# Nutribio

PWA mobile-first/responsive (React 19 + Vite + TypeScript + Tailwind CSS v4) —
weekly meal plans generated by Google Gemini from bioimpedance data. 100%
frontend, no backend; all state lives in `localStorage` (namespace `nutribio.v1`).
UI language: Portuguese (PT-PT). Code/identifiers/comments: English.

> **Monorepo (roadmap 4.1, DECISIONS #34):** the repo is an npm-workspaces
> monorepo — `apps/web` holds the shipped PWA (Vite, GitHub Pages),
> `packages/core` holds the shared pure logic (roadmap 4.2), `packages/db`
> holds the database schema + Supabase config (roadmap 4.3, DECISIONS #37) and
> `apps/api` holds the Nuxt API (roadmap 4.4, DECISIONS #44 — **local only**:
> not deployed until 4.8, not called by the web until 4.6).

> **2026-10 roadmap:** the 2026-10-06 decisions (#21–#30 in `docs/DECISIONS.md`)
> approve a backend/payment era (Nuxt API + Supabase, Stripe, 7 locales,
> country-aware cuisine, shopping list). Those changes are executed **per
> phase** tracked in **`docs/roadmap/`** — read it before planning any work.
> Until a phase lands, the constraints below describe the shipped app.

## ⚠️ READ THIS FIRST — Decisions that must NOT be undone

The most critical ones:

1. **No backend, no database, no sync** — data is intentionally single-device
   (localStorage). Do not add a server, accounts, or sync.
   *(Backend era: the database schema/Auth config exists in `packages/db`
   since roadmap 4.3 and the API exists in `apps/api` since 4.4, but the web
   app must keep writing only to `localStorage` until the consent gate 5.3 and
   the data layer 4.6 land, and the API is not deployed before 4.8 —
   DECISIONS #36/#43.)*
2. **Gemini API key lives ONLY in the Settings screen → localStorage.**
   Never bake it into the bundle or read it from env vars in production
   (the user explicitly rejected env vars because they are extractable from
   the shipped JS). `.env.example` is documentation only.
3. **Deterministic nutrition math is local** (`packages/core/src/calculations.ts`);
   Gemini receives the computed targets and only does the creative work
   (dishes, gram portions, weekly plan).
4. **Regeneration is ALWAYS user-confirmed** (dialog). Never auto-call the
   Gemini API on data changes or app start.
5. **Mobile-first does NOT mean mobile-only.** The layout must adapt: bottom
   tab bar + stacked sections on mobile; left sidebar + multi-column grids on
   desktop (`md+`). The user corrected this explicitly.
6. **Do not widen `apps/web/vite.config.ts` `server.allowedHosts`** — it is
   restricted to the user's tunnel host (`nbio.loca.lt`) on purpose.
7. **Preserve `profile.excludedFoods`/`observations`** in every profile write
   (editable in Settings/onboarding; other screens must pass them through).

## Commands

Run everything from the repo root; app commands target the `@nutribio/web`
workspace (there are no app scripts in the root `package.json`).

- `npm install` — install all workspaces (root `package-lock.json`)
- `npm run dev -w @nutribio/web` — dev server (http://localhost:5173; host allowed: `nbio.loca.lt`)
- `npm run build -w @nutribio/web` — i18n parity check (`i18n:check`) + core type-check + web type-check (`tsc --noEmit`, strict) + production build to `apps/web/dist/`
- `npm run typecheck -w @nutribio/core` — type-check the shared package only
- `npm run preview -w @nutribio/web` — serve the production build
- `npm run i18n:check -w @nutribio/web` — verify key parity + interpolation placeholders across all 7 locale catalogs
- `npm run icons -w @nutribio/web` — regenerate PWA icons (Python + PIL, `apps/web/scripts/generate_icons.py`)

Database / Supabase (`packages/db`, roadmap 4.3 — see `docs/SUPABASE_SETUP.md`):

- `npm run db:start|db:stop|db:status|db:reset -w @nutribio/db` — local Supabase stack (Docker: Postgres 54322, API 54321, Studio 54323, Mailpit 54324)
- `npm run db:generate -w @nutribio/db` — Drizzle → new SQL in `packages/db/supabase/migrations` (the schema in `packages/db/src/schema` is the source of truth)
- `npm run db:custom -- --name=<x> -w @nutribio/db` — empty custom migration (roles, grants, triggers, `auth.users` FKs)
- `npm run db:check|typecheck -w @nutribio/db` — migration consistency / strict TS
- `npm run db:verify|email:verify -w @nutribio/db` — local DB assertions and 7-locale OTP email checks (require the local stack)
- `npm run email:build -w @nutribio/db` — regenerate `supabase/templates/*.html` from `email/strings.mjs`
- `npm run auth:signing-key -w @nutribio/db` — generate the local ES256 JWT signing key (`supabase/signing_keys.json`, gitignored; restart the stack after it)
- `npm run db:link|db:push|config:push -w @nutribio/db` — **owner-only** commands against the hosted project (never run them unattended)

API (`apps/api`, roadmap 4.4 — see `docs/ARCHITECTURE.md` §16):

- `npm run dev -w @nutribio/api` — Nuxt dev server on port 3001 (needs `NUXT_DATABASE_URL`, `NUXT_SUPABASE_URL`, `NUXT_SUPABASE_SECRET_KEY`, `NUXT_CORS_ORIGINS`; see `apps/api/.env.example`)
- `npm run build|preview|typecheck -w @nutribio/api` — Nitro `node-server` build (`.output/`), serve it, strict TS
- `npm run test:integration -w @nutribio/api` — Vitest suite against the local Supabase stack with real ES256 tokens (requires `db:start` + the local signing key)

## Hard rules for `packages/core`

- No runtime dependencies, no DOM/Node globals (tsconfig has `lib: ES2022`,
  `types: []`) — the future API imports it too.
- No hidden state: pass the `locale` explicitly and the `Translate` function
  for labels (web adapter: `apps/web/src/i18n/translate.ts` → `coreT`).
- Failures are **codes** (`PlanParseError`), never translated strings.

## Quick map

| Path | Responsibility |
|---|---|
| `apps/web/` | the shipped PWA (Vite root: `index.html`, `vite.config.ts`, `public/`, `scripts/`) |
| `packages/core/` | `@nutribio/core` — pure shared logic (no deps, no DOM): types, locales, countries, calculations, meal slots/plan, shopping, hash, prompt, JSON schema, normalizers |
| `packages/db/` | `@nutribio/db` — database layer (roadmap 4.3): Drizzle schema for the private `app` schema, `createDb()` factory (API only), `supabase/config.toml` (local stack + Auth + Google + `remotes.production`), migrations and 7-locale auth email templates |
| `apps/api/` | `@nutribio/api` — Nuxt server only (roadmap 4.4): JWKS auth, CORS allow-list, code-based errors, health, profile/bio/history CRUD, account export/deletion; integration tests in `apps/api/tests` |
| `apps/web/src/i18n/` | i18n runtime + active-locale tracker (`locales.ts`), `Translate` adapter (`translate.ts`) and the 7 catalogs (`catalogs/`) |
| `packages/core/src/calculations.ts` | BMR (Mifflin-St Jeor + Harris-Benedict), TDEE, calorie ranges, macros, meal split |
| `packages/core/src/countries.ts` | `SUPPORTED_COUNTRIES` + country names/preselection (drives prompt cuisine) |
| `packages/core/src/prompt.ts` | Gemini prompt builder (English instructions + output-language + country blocks) |
| `packages/core/src/schema.ts` | Gemini structured-output JSON schema (`PLAN_SCHEMA`) |
| `packages/core/src/normalize.ts` | Response parsing/validation (`parsePlanResponse`, `normalizeWeek`) — errors as codes |
| `apps/web/src/lib/gemini.ts` | Gemini SDK call + retry; maps core parse error codes to localized messages |
| `apps/web/src/lib/models.ts` | Live Gemini model listing for the Settings dropdown |
| `apps/web/src/lib/storage.ts` | localStorage keys, defaults, bio record merge/remove, export/import |
| `packages/core/src/plan.ts` | Plan assembly + query helpers (selected dish, day/week totals) |
| `packages/core/src/shopping.ts` | Shopping list aggregation + quantity labels (Compras tab) |
| `packages/core/src/mealTimes.ts` | 5 meal slots + time windows, next-meal helpers |
| `packages/core/src/hash.ts` | FNV-1a inputs hash (plan cache invalidation; includes locale) |
| `apps/web/src/hooks/useStore.tsx` | Global state + persistence + plan generation action |
| `apps/web/src/screens/*` | Welcome (first-use landing gate), Onboarding (3-step wizard), Today, Plan, Shopping (Compras), Progress, EditData (Dados), Settings |
| `apps/web/src/components/*` | TabBar/Sidebar, forms (Field/NumberInput/TextArea), dialogs, charts, meal cards |
